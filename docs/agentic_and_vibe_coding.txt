Agentic Coding and Vibe Coding

"Vibe coding" is a term for writing software mostly by prompting an AI model and accepting what it generates, without carefully reading or understanding the code line by line. The developer describes what they want in plain language, the model produces code, it gets run, and if it seems to work the developer moves on. The term became popular because it captures a real shift in how some people build software: less time reading syntax, more time describing intent and reacting to results.

Vibe coding works well for throwaway scripts, quick prototypes, one-off data analysis, or exploring an idea before committing to it. In these cases the cost of a subtle bug is low and the goal is speed, not long-term maintainability.

"Agentic coding" is a related but different idea. An agentic coding tool does not just generate a single block of code from a prompt. It can plan a multi-step task, decide which files to read or edit, run commands like tests or builds, look at the output, and adjust its next step based on what it finds. It behaves less like an autocomplete and more like a junior developer working through a task somewhat independently, checking its own work along the way.

The two terms overlap but are not the same thing. Vibe coding describes a style of working with AI output (trust it, don't scrutinize it too closely). Agentic coding describes a capability of the tool (it can take multiple actions in sequence, not just answer one prompt). It is possible to use an agentic tool while still vibe coding with it, by accepting every change it proposes without review. It is also possible to use a simple, non-agentic AI assistant carefully, reading and testing every suggestion before accepting it.

The main risk with vibe coding is that AI-generated code can look correct while containing real problems: security issues like unvalidated user input, logic that only works for the cases the developer happened to test, silent failures that don't throw an error but produce wrong results, or dependencies that don't actually exist. None of these are obvious just by skimming the output or seeing that a program runs without crashing.

Agentic tools reduce some of this risk because they can run tests, check build output, and catch certain classes of errors automatically before a human ever sees the code. But this only helps if the tests and checks are actually meaningful. An agent that runs a shallow test suite and reports success is not a substitute for a developer who understands what the code is supposed to do.

A few practices make both approaches safer in practice. Reading the diff before accepting a change catches obvious mistakes and keeps the developer aware of what's actually in their codebase. Running tests, not just trusting that code "looks right," catches logic errors. Keeping changes small and reviewable makes it realistic to actually check them, instead of accepting a huge block of generated code all at once. Using version control means any mistake can be rolled back. Being especially careful around authentication, payments, user input, and anything touching real data matters more than being careful around a throwaway script, since the cost of a bug is much higher there.

The practical takeaway: vibe coding and agentic coding are not inherently good or bad, they are tools suited to different situations. Fast prototyping benefits from moving quickly and not overthinking every line. Production systems, anything handling user data, and anything other people will depend on benefit from the opposite: slower, more deliberate review, even when an AI agent did most of the initial work.
